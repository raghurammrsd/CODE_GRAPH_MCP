Core Philosophy

The Problem with AI Code Exploration

AI coding agents currently rely on brute-force text search (grep / ripgrep) to navigate repositories. In enterprise codebases, this pattern introduces major operational bottlenecks:

01

Context Window Saturation

Dumping 2,000-line files to find one caller exhausts 80% of an LLM prompt. CodeGraph slices targeted 50-line AST ranges, reducing token usage by 65% to 85%.

02

Relationship Hallucinations

Text search cannot determine if a function is called, injected, or overridden. CodeGraph proves multi-hop call chains with fail-closed evidence.

03

Database & Route Blindspots

Agents lose track of FastAPI prefix mounts and ORM table writers. CodeGraph indexes composite route trees and database readers/writers statically.

Setup Guide

30-Second Quickstart

Install from PyPI, automatically onboard your AI editor, and initialize your project index.

1. Install Package

Install the engine and MCP server dependencies:

pip install "codegraph-engine[mcp]"
2. Onboard AI Agents Automatically

Detects Claude Code, Cursor, Antigravity, and Cline; configures `mcpServers` and safe instructions:

codegraph install --yes --target auto --location local
3. Initialize Index & Verify Readiness

Indexes the local codebase into an embedded SQLite database (`.codegraph.sqlite3`):

cd my-project
codegraph init
codegraph doctor --database
4. Optional: Run With Dev Server Telemetry

Transparent 1-line wrapper to capture live HTTP routes and exceptions directly into the graph:

codegraph run npm run dev
# or for Python FastAPI:
codegraph run uvicorn main:app --reload

Command Line Interface

CLI Reference & Problem Solving Guide

Detailed breakdown of every `codegraph` command, what operational bottlenecks it resolves, and real execution outputs.

codegraph init [PATH] Core Lifecycle

Initialize repository indexing and configuration.

Problem Solved: Creates the persistent SQLite index (.codegraph.sqlite3) and sets up the project graph cache without requiring external DB infrastructure.
Flags & Options:
  • --repository, -r : Repository path
  • --json: Machine-readable JSON output
$ codegraph init .

Initialized CodeGraph repository at /path/to/repo (indexed 190 files)
codegraph index [PATH] Core Lifecycle

Perform incremental AST & relationship indexing with 16-phase telemetry.

Problem Solved: Detects modified or deleted files using content hashes and Git commits; only re-indexes what changed in milliseconds.
Flags & Options:
  • --verbose, -v: Show phase-by-phase timings and memory usage
  • --quiet, -q: Suppress progress blocks
  • --json: Output phase metrics as JSON
$ codegraph index . --verbose

Phase: Repository Scan [190/190 files, 100%] elapsed: 0.09s
Phase: Final Commit & Checkpoint
scanned=190 indexed=1 unchanged=189 removed=0
codegraph status [PATH] Health & Freshness

Inspect index freshness, file counts, and resource consumption in < 5ms.

Problem Solved: Eliminates slow full-repo scans before queries by checking git commit HEAD match and working tree status instantly.
Flags & Options:
  • --repository, -r : Repository path
$ codegraph status .

{
  "status": "FRESH",
  "files": 190,
  "symbols": 1944,
  "graph_edges": 14293,
  "resource_profile": "BALANCED"
}
codegraph doctor [PATH] Health & Freshness

Verify SQLite schema integrity, foreign keys, FTS search, and orphaned processes.

Problem Solved: Detects database corruption, schema mismatches, duplicate canonical symbol IDs, and stale background processes.
Flags & Options:
  • --database: Run deep schema & foreign key checks
  • --processes: Audit active MCP processes and parent PIDs
  • --json: Output diagnostic report as JSON
$ codegraph doctor --database

{
  "status": "OK",
  "database_version": 8,
  "foreign_keys": true,
  "issues": []
}
codegraph run Runtime Telemetry

Zero-friction runtime telemetry interceptor.

Problem Solved: Bypasses the complexity of setting up OpenTelemetry or Pino streaming. Injects lightweight NODE_OPTIONS or PYTHONSTARTUP hooks to record live HTTP routes, latencies, and uncaught exceptions directly into SQLite.
Flags & Options:
  • --sample-rate : Trace sampling rate (0.0 to 1.0, default 1.0)
$ codegraph run npm run dev
# or
codegraph run uvicorn main:app --reload

>> Dev server active on port 8000
[CodeGraph Runtime Interceptor: Captured 14 HTTP spans -> .codegraph/runtime.sqlite3]
codegraph serve [PATH] MCP Server

Run the Model Context Protocol (MCP) server over stdio or SSE HTTP.

Problem Solved: Connects AI coding agents (Claude, Cursor, Antigravity) to the repository intelligence graph via JSON-RPC standard I/O or persistent SSE HTTP.
Flags & Options:
  • --profile : Tool profile (core | minimal | agent | developer | full)
  • --transport, -t : Transport layer (default
  • --host : Host for SSE server (default
  • --port, -p : Port for SSE server (default
$ codegraph serve . --transport sse --port 8765

CodeGraph MCP server running on http://127.0.0.1:8765/sse (56 tools registered)
codegraph stop [PATH] Process Lifecycle

Safely terminate active CodeGraph background processes and release SQLite file locks.

Problem Solved: Prevents "database is locked" crashes by gracefully signalling MCP servers to close connections before unmounting or updating.
Flags & Options:
  • --all, -a: Stop all CodeGraph processes across all repositories
  • --timeout : Graceful shutdown timeout before SIGKILL
  • --json: Output machine-readable JSON
$ codegraph stop --json

{
  "status": "ok",
  "stopped_count": 1,
  "stale_cleaned_count": 0
}

codegraph context Context Optimization

Compile token-budgeted ContextPacket for an AI agent task.

Problem Solved: Selects the top high-signal symbols and slices needed for a specific task intent (DEBUG, TRACE, REVIEW) fitting strictly within a token budget.
Flags & Options:

  • --max-tokens : Token limit (default
  • --json: Output serialized ContextPacket
